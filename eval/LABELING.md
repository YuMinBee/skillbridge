# 라벨링 가이드

평가 정답셋을 만드는 규칙입니다. 두 사람이 **서로의 라벨을 보지 않고** 따로 붙인 뒤 일치도(Cohen's κ)를 잽니다.

| 파일 | 내용 | 1차 라벨 | 2차 라벨 |
|---|---|---|---|
| `gold_postings.jsonl` | 잡알리오 실공고 30건의 요구 스킬 | `claude-draft` (AI 보조 초안) | 팀원 → `gold_postings_b.jsonl` |
| `synthetic_candidates.jsonl` | 갭을 심은 합성 지원자 30명 | 생성 시 정답이 정해짐 (`gen_synthetic_candidates.py`) | 필요 없음 |
| `gold_courses.jsonl` | 스킬별 과정 적합도 | `claude-draft` | 팀원 검수 |

## 1. 공고 스킬 라벨

공고 본문(자격요건·우대사항)을 읽고 **지원자에게 요구하거나 우대하는 기술 역량**을 `data/skills.csv`의 `skill_id`로 붙입니다. 사전을 열어 두고 붙이되, 사전에 있는 표현인지가 아니라 **뜻**으로 판단합니다. 예를 들어 "OA프로그램 활용"은 사전에 없는 표기지만 `office`입니다.

**스킬로 본다**
- 프로그램·도구: 한글·엑셀·파워포인트·MS오피스 → `office`, 엑셀이 따로 적혀 있으면 `excel`도 붙입니다.
- 자격증: 컴퓨터활용능력 → `cert_computer`, 워드프로세서·ITQ·MOS·사무자동화 → `cert_office`, 정보처리(산업)기사·기능사 → `cert_info_processing`, 정보보안(산업)기사 → `cert_security`, 정보통신(산업)기사·네트워크관리사 → `cert_network`, ADsP·SQLD·빅데이터분석기사·"데이터전문가" → `cert_data`
- 통계 도구: SPSS·SAS·"통계프로그램" → `stat_tool`, R → `r_lang`
- 분야 경험·전공: 그 분야 지식을 요구하는 것으로 봅니다. 단, 사전 스킬과 분명히 대응할 때만 붙입니다.
  - 통계학 → `statistics`
  - 인공지능·AI 사업 → `ai_general`
  - 데이터사이언스·빅데이터 통계 → `data_analysis`
  - 정보보호·보안관제 → `security`
  - 정보통신 → `networking`
- 어학: 공인영어성적(TOEIC 등) → `english`
- 논문 실적 → `paper_research`

**스킬로 보지 않는다**
- 운전면허, 면허(간호사·약사 등), 기술 외 자격증(전기·조경·한국사 등)
- 가산점 대상(보훈·장애인·지역인재), 학력·연령·병역
- "관련 자격증", "해당분야 기사"처럼 무엇인지 특정할 수 없는 표현
- 모집 부문 이름("AI·데이터 부문")만 있고 요구 내용이 없는 경우
- 사회과학 전공 이름 속 단어 (예: "미디어·커뮤니케이션학"의 커뮤니케이션)

**필수/우대 구분**
- 자격요건(필수) 영역에 있으면 `required`
- 우대사항 영역에 있거나 "(우대)", "[우대]"가 붙어 있으면 `preferred`
- 같은 스킬이 두 곳에 있으면 `required`

**사전에 없는 기술**은 `oov`에 적습니다(예: CAD, GIS, 정보시스템감리사). 지표 계산에는 들어가지 않고, 사전을 넓힐 후보로 씁니다.

## 2. 과정 적합도

갭 스킬을 메우려는 사람에게 그 과정이 맞는지 **과정 제목**으로 판단합니다.

| 값 | 기준 | 예 |
|---|---|---|
| 2 | 그 스킬이 과정의 주제 | LLM 갭 → "LLM 파인튜닝 A to Z" |
| 1 | 여러 주제 중 하나 | AWS 갭 → "AWS & CI/CD 기반 Java Full-Stack" |
| 0 | 이름만 겹치고 다른 목적 | LLM 갭 → "챗GPT 실무 올인원(문서·리서치)" |

## 3. 표본

`eval/sample_postings.py`로 다시 만들 수 있습니다(seed 6). 디지털 단서가 있는 공고 20건과 무작위 10건을 뽑습니다. 단서 정규식은 표본을 고르는 데만 쓰고, 라벨과는 무관합니다.

## 4. 2차 라벨 만드는 법

1. 라벨을 비워 둔 `gold_postings_b.todo.jsonl`을 `gold_postings_b.jsonl`로 복사합니다. (`gold_postings.jsonl`은 열지 않습니다. 1차 라벨이 보입니다.)
2. 각 줄의 `annotator`에 본인 이름을 적습니다.
3. 위 규칙대로 `labels`를 채웁니다. 예: `{"office": "preferred", "excel": "preferred"}`
4. `.\tasks.ps1 eval`을 실행하면 보고서 5절에 κ가 나옵니다. κ가 0.6 이상이면 합의 가능한 수준입니다.
5. 두 라벨이 다른 항목은 둘이 의논해 `gold_postings.jsonl`을 고치고, 바꾼 규칙은 이 문서에 추가합니다.
