# 역량다리 구현 명세 (Claude Code 작업 지시서)

이 문서는 Claude Code가 이 프로젝트를 처음부터 구현하기 위한 지시서다. 위에서부터 순서대로 읽고, **9장 마일스톤 순서대로** 작업한다. 판단이 필요한 부분은 이 문서의 원칙을 따르고, 문서에 없는 결정은 가장 단순한 쪽을 고른 뒤 `DECISIONS.md`에 한 줄로 기록한다.

함께 주는 파일: `skillbridge-demo.html` (화면 구성과 동작을 보여주는 정적 프로토타입. UI는 이 파일을 기준으로 만든다.)

## 2. 서비스 컨셉

**한 줄**: AI·클라우드 채용시장을 분석해 **기업이 필요한 역량과 교육 트랙을 내놓고**, 취준생은 **시장 기준과 그 기업 기준**으로 자기 갭을 진단받아 **맞춤 학습경로**를 추천받는 Bedrock 에이전트.

차별점 (구현과 시연에서 반드시 드러나야 함)

1. **양방향 구조**: 기업 콘솔에서 요구역량·교육 트랙을 바꾸면 취준생 진단 결과가 즉시 바뀐다.
2. **공고만 본 추천 vs 기업 기준 추천 비교**: 일반 개인 에이전트(공고 문구만 사용)가 놓치는 갭과 불필요한 공부를 수치로 보여준다.
3. **측정된 품질**: 스킬 추출 정확도, 갭 탐지 recall, 추천 Hit@k를 직접 만든 정답셋으로 측정해 리포트한다.
4. **근거가 있는 추천**: 모든 추천에 근거(공고 문장, 시장 언급률, 기업 등록 기준)를 붙인다. LLM은 근거를 인용해 설명만 하고, 점수는 규칙으로 계산한다.
5. **책임 있는 설계**: 개인 진단 결과는 본인에게만, 기업에는 익명 집계만 준다. 채용 합불 판단에 쓰지 않는다고 화면에 명시한다.

## 3. 사용자와 화면

`skillbridge-demo.html`의 세 탭을 실제 기능으로 만든다.

### ① 시장 분석 (누구나)
- 필터: 지역(대경권 / 전국), 직무(AI 엔지니어 / 클라우드 엔지니어)
- 공고 요구 빈도 상위 스킬 막대그래프 (언급 비율 %), 분석 공고 수 표시
- 급상승 스킬 (직전 6개월 대비 언급 비율 변화 %p)
- 근거 공고 예시 문장 (출처·날짜 포함)

### ② 취준생 진단
- 입력: 이력서 텍스트 붙여넣기 또는 PDF 업로드, 목표 기업 선택, 주당 학습 가능 시간
- 출력
  - **준비도 점수** (규칙 기반, 공식 화면 노출)
  - **역량 갭 매트릭스**: 스킬 / 필수·우대 / 내 상태(보유·부분·검증 필요·없음) / 근거
  - **맞춤 학습경로**: 필수 갭 우선, 공공 과정으로 기초 → 기업 트랙으로 마무리. 총 시간과 예상 주 수
  - **공고만 본 추천 vs 기업 기준 추천** 비교 패널
  - **다른 기업과 비교**: 같은 프로필의 기업별 준비도와 첫 학습 과제
  - **에이전트 실행 단계 trace** (각 단계 이름과 호출한 도구 표시)
- 시연용 예시 지원자 3명을 기본 제공한다 (데모 HTML의 p1~p3).

### ③ 기업 콘솔
- 기업 선택 (시연용 가상 기업 3곳: 데모 HTML의 A·B·C)
- 요구역량 편집: 스킬별 필수(2) / 우대(1) / 제외, 시장 언급률과 함께 스킬 추가
- 기업 교육 트랙 등록·수정 (대상 스킬, 제목, 시간, 혜택 문구)
- 기업 자료 업로드 (JD, 기술블로그 글, 스택 설명) → 지식베이스에 들어가고 요구역량 초안을 자동 제안
- 지원 희망자가 가장 많이 막히는 역량 (익명 집계, 비율)
- 우리 공고 vs 시장: 시장 언급률이 낮은 스킬을 필수로 두면 경고

## 4. 아키텍처

리전은 **서울(ap-northeast-2)**, 인증은 팀 SSO 프로필 `kosa`.

```
[수집] EventBridge(스케줄) → Lambda(collector) → S3 raw/
[정제] Lambda(extractor): Bedrock 구조화 출력으로 스킬 추출 → 정규화 → S3 curated/ (Parquet 또는 JSONL)
[집계] Athena: 지역·직무·월별 스킬 언급률, 급상승 스킬
[기업 KB] S3 corp-docs/{tenantId}/ + .metadata.json → Bedrock Knowledge Base (S3 Vectors, Titan Text Embeddings V2)
[API] FastAPI (로컬 실행 + Lambda 배포 가능하게 Mangum 사용)
[에이전트] 고정 순서 파이프라인: Lambda/FastAPI에서 Bedrock Converse API를 단계별로 호출
[화면] React(Vite) SPA, 데모 HTML의 레이아웃과 동작을 따른다
[저장] 기업 설정·트랙·익명 집계: DynamoDB 또는 SQLite(로컬 모드)
```

결정 사항과 이유

- **에이전트 구현**: 단계가 정해져 있으므로 Bedrock Agents/AgentCore 대신 **Converse API를 순서대로 호출하는 파이프라인**으로 만든다. 단계별 입출력을 trace로 남겨 화면에 보여준다. 시간이 남으면 같은 도구들을 Strands Agents 툴로 감싸 "자유 질의" 모드를 추가한다(선택).
- **스킬 추출**: Bedrock **structured outputs(JSON 스키마 강제)** 사용. 숫자 범위 제약은 안 되므로 상태·구분 값은 문자열 enum으로 정의한다.
- **벡터 저장소**: **S3 Vectors** (서울 리전 지원). **OpenSearch Serverless는 쓰지 않는다** (최소 OCU 상시 과금).
- **멀티테넌시**: 지식베이스 하나를 공유하고 문서마다 `tenantId` 메타데이터를 붙인다. 필터는 **서버에서 강제로** 넣는다. 클라이언트가 보낸 tenantId를 그대로 믿지 않는다.
- **정확한 스킬 매칭은 RAG가 아니라 정규화 테이블**로 한다. S3 Vectors는 하이브리드 검색이 안 되므로 KB는 기업 문서 근거 검색에만 쓴다.
- **임베딩**: Titan Text Embeddings V2 (서울 리전 사용 가능). 한국어 질의·한국어 문서로 맞춘다.
- **LLM 모델 ID는 환경변수**로 둔다. 팀 계정에서 접근 확인된 모델을 쓴다 (교육 노트북 `00_환경점검` 2-1에서 통과한 모델. inference profile 접두사 `apac.` 또는 `global.` 필요 여부를 확인).
- **개인정보**: 이력서 입력은 Bedrock Guardrails의 PII 필터(한국어 지원)로 이름·연락처를 마스킹한 뒤 처리하고, 원문은 저장하지 않는다.

## 6. 스킬 체계와 파이프라인

### 6.1 2계층 스킬 사전
- **아래층**: AI·클라우드 중심 canonical 스킬 300~800개. `data/skills.csv`
  - 컬럼: `skill_id, canonical, category, aliases_ko, aliases_en, onet_ref, ncs_unit`
  - 별칭 예: PyTorch ← 파이토치, torch / Kubernetes ← 쿠버네티스, k8s
  - O*NET Technology Skills(CC BY 4.0)와 Stack Overflow 기술 목록을 바탕으로 만들고, 한국어 별칭은 LLM으로 초안 생성 후 사람이 검수한다는 전제로 `reviewed` 컬럼을 둔다.
- **위층**: NCS 능력단위. 스킬 → NCS 코드 매핑으로 "왜 이 훈련과정인가"를 설명하고 훈련과정과 연결한다.

### 6.2 공고 처리
1. 공고를 섹션으로 분리: 담당업무 / 자격요건 / 우대사항 (규칙 + LLM 보조)
2. LLM 구조화 출력으로 언급 추출: `{mention, section, requirement: "required"|"preferred", evidence}`
3. 정규화: 별칭 사전 정확 매칭 → 실패분만 임베딩 top-k 후보에서 LLM이 고르거나 `none` 판정
4. 결과를 `posting_skills` 테이블로 저장 (공고 ID, 스킬 ID, 구분, 근거 문장)

### 6.3 이력서 처리
- 같은 추출·정규화 파이프라인을 쓰고, 상태를 판정한다.
  - `own` 보유: 프로젝트·업무 등 구체적 근거 있음
  - `part` 부분: 수업·짧은 경험 등 근거가 약함
  - `verify` 검증 필요: 키워드만 있고 근거 없음
  - `miss` 없음
- 각 판정에 근거 문장을 함께 저장한다.

### 6.4 점수 (규칙 고정, LLM 사용 금지)
```
준비도 = Σ(가중치 × 상태값) / Σ가중치 × 100
가중치: 필수 2, 우대 1
상태값: own 1.0, part 0.5, verify 0.5, miss 0
```
- 같은 입력이면 항상 같은 점수. 공식은 화면에 그대로 노출한다.

### 6.5 학습경로
- 갭 정렬: 필수 먼저, 같은 구분 안에서는 상태값이 낮은 순
- 스킬별 후보: 공공 과정(훈련과정 API) + 기업 트랙
- `verify` 상태는 강의 대신 "결과물로 증명하기" 과제를 제안
- 주당 시간으로 총 기간 계산
- 설명문은 LLM이 쓰되 **입력으로 준 근거만 인용**하게 프롬프트를 제한하고, 근거 ID가 출력에 없으면 재생성한다

### 6.6 "공고만 본 추천" 기준선
- 같은 지원자에 대해 기업 등록 기준 대신 그 기업 공고 문구에서 뽑은 스킬만으로 갭을 계산한다.
- 차이를 "놓친 갭 / 불필요한 공부 / 준비도 변화"로 보여준다.

## 7. 평가 (분석 품질·추천 성능 점수용, 필수)

`eval/` 폴더에 정답셋과 스크립트를 두고 `make eval` 한 번으로 표가 나오게 한다.

| 단계 | 정답 데이터 | 지표 |
|---|---|---|
| 스킬 추출·정규화 | 공고 25건을 두 사람이 라벨링 (`eval/gold_postings.jsonl`) | Precision / Recall / F1 |
| 갭 탐지 | 갭을 일부러 심은 합성 지원자 30명, 한국어 표기 변형 포함 (`eval/synthetic_candidates.jsonl`) | 갭 recall, 오탐률 |
| 추천 | 갭별로 적합한 과정 표시 (`eval/gold_courses.jsonl`) | Hit@3, nDCG@5 |
| 사용자 | 5~10명 5점 척도 설문 | 평균 만족도 |

- **ablation 표 필수**: ① 별칭 사전만 ② + 임베딩 후보 ③ + LLM 재랭킹. 각 단계 F1을 비교한다.
- 공고만 본 추천 vs 기업 기준 추천의 Hit@3 비교도 같은 표에 넣는다.
- 결과는 `eval/report.md`로 저장하고 화면의 "품질" 섹션(시장 탭 하단 또는 별도 페이지)에서 보여준다.
- 라벨링 가이드를 `eval/LABELING.md`로 쓴다 (무엇을 스킬로 볼지, 경계 처리 규칙).

## 9. 마일스톤 (이 순서대로)

**M0. 골격 (반나절)**
- 저장소 구조, `.env.example`, Makefile, FastAPI·React 빈 앱
- `BEDROCK_MOCK=1`이면 Bedrock 호출을 고정 응답으로 대체하는 어댑터
- 완료 조건: `make run`으로 세 탭이 데모 HTML과 같은 레이아웃·샘플 데이터로 뜬다

**M1. 규칙 엔진 (1일)**
- 스킬 사전 초안(최소 150개), 점수, 갭 정렬, 학습경로, 공고만 본 기준선, 기업 간 비교
- seed 데이터만으로 취준생 탭 전체가 동작
- 완료 조건: 점수·경로 단위 테스트 통과, 기업 콘솔에서 요구역량을 바꾸면 진단이 즉시 바뀜

**M2. Bedrock 연결 (1~2일)**
- 공고·이력서 구조화 추출, 정규화(사전 → 임베딩 후보 → LLM 판정), 설명 생성(근거 인용 검증 포함)
- Guardrails PII 마스킹
- trace 기록과 화면 표시
- 완료 조건: `BEDROCK_MOCK=0`에서 예시 지원자 3명 진단이 끝까지 돌고, 단계별 trace가 보임

**M3. 공공 데이터 수집 (1~2일)**
- 훈련과정, 공공 공고, NCS collector와 `DATA_MODE` 전환
- S3 raw/curated 적재, Athena 집계 쿼리, 시장 탭을 실제 집계로 교체
- 완료 조건: 수집 메타데이터에서 "데이터 출처·범위·한계" 표가 자동 생성됨

**M4. 기업 지식베이스 (1일)**
- S3 Vectors KB 생성, 가상 기업 문서 적재, tenantId 서버 강제 필터
- 기업 자료 업로드 → 요구역량 초안 제안
- 완료 조건: 다른 tenant의 문서가 검색되지 않는 테스트 통과

**M5. 평가 (1~2일, 팀원 라벨링과 병행)**
- 라벨링 가이드, 정답셋 로더, 지표 계산, ablation 표, `eval/report.md`
- 완료 조건: `make eval` 한 번으로 표 생성

**M6. 배포와 시연 준비 (1일)**
- Lambda + API Gateway(또는 Function URL) 배포, 프런트 정적 호스팅(S3)
- 시연 시나리오 스크립트(`docs/DEMO_SCRIPT.md`): 시장 → 기업 A 요구역량 수정 → 같은 지원자가 A와 B에서 다른 경로 → 공고만 본 추천과 비교 → 품질 표
- 완료 조건: 인터넷이 끊겨도 `BEDROCK_MOCK=1, DATA_MODE=sample`로 시연 가능

## 10. 지켜야 할 것

- 비용: OpenSearch Serverless 금지. 모든 리소스에 `project=kosa06` 태그. 대량 공고 추출은 배치 추론(온디맨드 대비 50%)을 고려하되 최소 건수 조건을 먼저 확인.
- 보안: 키·토큰은 `.env`와 AWS Secrets Manager에만. 저장소에 커밋 금지.
- 다른 팀 계정 주의: SSO 포털에서 계정이 kosa06인지 확인하고 작업한다.
- 화면 문구: 개인 진단은 본인에게만 보이며 채용 합불 판단에 쓰이지 않는다는 안내를 진단 화면과 기업 콘솔에 표시한다.
- 추천 과정은 실제 카탈로그(API 응답 또는 seed)에 있는 것만 낸다. LLM이 과정명을 지어내면 안 된다.
- 모든 화면은 다크/라이트 모드, 모바일 폭에서 깨지지 않게.

## 11. 먼저 확인할 것 (M0과 함께)
