# 현업 청취: 부서별 채용 기준 (7개 업체)

- **출처:** 현업 멘토가 업체 대표와 인사 담당자에게 들은 내용을 정리해 2026-11-13에 보내 주신 것이다. 업체명은 익명이다.
- **반영 범위:** IT 직무 4곳은 기업 E·F·G·H로 넣었다(`seed/companies/E~H.json`). 나머지 3곳은 반영하지 않았고, 이유는 아래에 적었다.

## 현업이 공통으로 한 말

1. **기준은 부서마다 다르다.** 회사 인재상은 따로 있지만, 역량은 그 부서에 필요한 것만 본다.
2. **프로젝트 경험은 필수다.** 다만 중요한 것은 그 경험이 *해당 부서에 필요한 경험이었는지*다.
3. "근면 성실" 같은 원론은 공통으로 나왔지만, 역량 기준이 아니어서 뺐다.

→ 1은 우리 설계(기업이 직무 단위로 기준을 등록한다)를 뒷받침한다. 2는 **프로젝트 적합도**로 구현했다(`backend/app/pipeline/projectfit.py`, 2026-11-13).

- 이력서를 경험 단위(프로젝트·인턴·연구 한 줄, 들여쓴 줄은 앞 경험에 붙임)로 나눈다. 보유기술·학력·교육 목록은 경험으로 치지 않는다.
- 경험 하나 안의 스킬만으로 그 부서 실무 준비도를 계산한다(규칙, 기존 공식 그대로). 경험 문장에 부서 도메인 단어(기업 seed `domain`, 팀이 정함)가 있는지도 본다.
- 판정: 50점 이상이고 도메인이 일치하면 "이 부서에 맞는 경험", 25점 이상이면 "일부만 맞음", 그 아래는 "거리가 있음".
- 맞는 경험이 없으면 그 부서용 미니 프로젝트를 제안한다. '결과물에 보여줄 것'은 현업 문항 원문을 그대로 쓴다.
- 같은 이력서를 다른 기업과 비교할 때 기업별 "가장 맞는 경험" 점수도 함께 보여준다.
- 한계: 50점·25점 경계와 도메인 단어는 팀이 정한 값이고, 현업 검증 전이다. 멘토링에서 확인받을 항목이다.

## 반영 방식

공개 공고가 없으므로 다음과 같이 대응했다.

- **지원 기준:** 현업이 '필수'라고 말한 항목(`apply_requirements`, 출처 표시 "현업 필수")
- **실무 기준:** 필수와 우대를 합친 항목

화면에는 스킬마다 원문 문항이 출처로 붙는다(`sources`).

| ID | 업체·부서 | 필수 → 스킬 | 우대 → 스킬 |
|---|---|---|---|
| E | 군수납품 · 제품 품질관리 | 전자 회로, 기초 프로그래밍(→Python) | C언어, 방산·드론 도메인 프로젝트, 영상처리(→컴퓨터비전), 정보처리기사 |
| F | 웹 서비스 · 서비스 운영 | Docker, 클라우드 네트워크(→네트워크), REST API | 보안 프로젝트, Nginx 리버스 프록시 |
| G | 개발 외주 · 서비스 품질관리 | Git, DB 관계(→SQL) | 백엔드 활동 경험(→REST API), 데이터 모델링, 인덱스·실행 계획(→쿼리 튜닝) |
| H | 게임 개발 · 클라이언트 | C#·OOP, Unity 생명주기, UGUI | 패치·동적 리소스, 렌더링 최적화, 메모리·프레임 최적화 |

**대응 판단(팀 결정):**

- "기초 프로그래밍 언어(언어 무관)"는 사전에 '아무 언어나'를 나타낼 방법이 없다. 그래서 과정 매칭이 되는 Python으로 대응했다.
- "해커톤 등 백엔드 활동 경험"은 프로젝트 경험이다. 그래서 가장 가까운 REST API로 대응했다.

**사전에 추가한 스킬 10개:**

- C언어, 전자 회로, 방산·드론 도메인
- Unity, UGUI, 패치·동적 리소스, 렌더링 최적화, 메모리·프레임 최적화
- 데이터 모델링, 쿼리 튜닝

평가 숫자는 추가 전과 같다. 처음에는 C언어의 표준 이름을 "C" 한 글자로 넣었다. 그러자 공공 공고의 "전문관리직(C)"를 C언어로 잡았고, 사전만 쓴 F1이 0.744에서 0.736으로 떨어졌다. 표준 이름을 "C언어"로 바꿔 해결했다. 정답셋에 맞춘 조정이 아니라, 한 글자 별칭을 막은 일반 수정이다.

**과정 공급:** 고용24 카탈로그(199개)에 Unity, UGUI, Git, REST API, 정보처리기사, 전자 회로 과정이 없다. 그래서 이런 갭은 과정을 지어내지 않고 "자습 + 미니 결과물"로 안내한다. 이 자체가 공급 공백의 근거다.

## 반영하지 않은 3곳

| 업체·부서 | 필수 | 반영하지 않은 이유 |
|---|---|---|
| 게임 개발 · 디자인 | 캐릭터 디자인, 원화·오리지널 캐릭터 | 포트폴리오로 판단하는 역량이다. 텍스트 이력서의 스킬 추출로는 판정할 수 없다 |
| 소방 안전 관리 · 점검팀 | 점검자 경력수첩 | 비IT 자격·경력이다. 스킬 사전과 과정 카탈로그 범위 밖이다 |
| 부품 제조 · 양극재 제조팀 | 품질기사, **군필 여부** | 비IT다. 특히 군필·학과 같은 **역량이 아닌 속성은 점수에 넣지 않는다**(준비도는 배울 수 있는 역량만 잰다) |

이 3곳은 "적용 범위"를 설명할 때 근거로 쓴다. 자격증 중심 직무는 사전과 카탈로그만 넓히면 같은 구조로 들어온다. 포트폴리오 중심 직무는 다른 판정 방식이 필요하다.
